# FastTabClick 需求分析文档（v0.1 草案，待核对）

## 1. 一句话需求

Windows 后台小工具（Rust，无界面）：按住 **左 Alt + 右键**，把鼠标位置**正下方被盖住的窗口**立即唤到前台，实现"隔空穿透点击切换"，替代 Alt+Tab / 任务栏点选。

## 2. 背景与痛点

- 场景：写代码（IDE 全屏或置前）时频繁切 IM 回消息（微信 / 企业微信 / 飞书 / Slack），每天上百次。
- 现有切换方式成本高：
  - Alt+Tab：顺序不稳定，两步操作（按键 + 视觉搜索目标）；
  - 任务栏点选：需要精准瞄准，容易误点；
  - IDE 最大化时聊天窗被完全盖住，甚至不知道它在哪。
- 你最初的设想："记录每个软件窗口的位置，按快捷键时根据鼠标坐标匹配"。
  **关键洞察：这一步"记录"可以省掉**，Windows 提供了实时查询窗口位置与层叠关系的接口（见 5.1 / 5.2）。

## 3. 典型使用场景（核心闭环）

IDE 在前台最大化，飞书被盖在后面（可能被完全遮挡）：

1. 鼠标移到飞书窗口所在区域内的任意位置；
2. 按下 左Alt + 右键 → 飞书立即置前并获得键盘焦点，回消息；
3. 再按一次 左Alt + 右键 → 此时飞书在顶、IDE 在第二层 → IDE 回到前台。

两次同一操作，天然形成 **IDE ↔ IM 的乒乓切换**，正好覆盖你的核心场景。被盖住的窗口即使完全不可见，只要它的矩形区域包含鼠标点，就能被找到并激活——这是它比"点击切换"强的本质。

## 4. 核心逻辑（按下快捷键后发生什么）

1. 取鼠标坐标；
2. 枚举系统所有可见、未最小化的顶层窗口（`EnumWindows` 返回顺序即 Z 序：从顶层往下）；
3. 筛出"窗口矩形包含鼠标点"的窗口 → 得到该位置的**窗口层叠栈**；
4. 取栈中**不是当前前台窗口**的第一个（即紧贴着可见顶层的那个被盖窗口）；
5. 激活它（`SetForegroundWindow`，需绕过前台锁，见 5.3）；
6. **吞掉本次右键事件**（回调返回非 0），避免目标程序弹出右键菜单；普通右键不受任何影响。

## 5. 技术分析（本次核对的重点）

### 5.1 系统有没有现成接口？——原料齐全，没有半成品

| 需要的能力 | Windows API | 说明 |
|---|---|---|
| 全局监听鼠标 + 判断 Alt 状态 | `SetWindowsHookExW(WH_MOUSE_LL)` | 系统低层鼠标钩子，可读修饰键、可吞事件 |
| 查鼠标点下方的窗口 | `WindowFromPoint` / `EnumWindows` + `GetWindowRect` | 实时查询，**无需自己记录位置** |
| 按 Z 序枚举窗口 | `EnumWindows` | 天然按"从顶层到底层"顺序返回 |
| 窗口置前 | `SetForegroundWindow`（配 AttachThreadInput 技巧） | 有系统限制，见 5.3-1 |
| 窗口位置变化事件 | `SetWinEventHook(EVENT_OBJECT_LOCATIONCHANGE)` | 只有走"记录位置"路线才需要，实时查询方案用不到 |

结论：所有"原料"系统都有，但**没有任何内置功能直接实现"激活鼠标下方的被盖窗口"**，需要自己组装成小工具——这正是本项目的价值。

### 5.2 为什么可以丢掉"记录位置"的设计

- 热键触发时实时枚举，几十个窗口耗时约 1ms，完全无感；
- 零状态 = **开箱即用、永远准确**：窗口移动、改尺寸都不存在"记录过期"问题；
- 若未来想做"窗口布局快照/恢复"（类 FancyZones），才需要持久化记录——不进 MVP。

### 5.3 三个已知的硬骨头（社区均有成熟解法，列出来供你评估风险）

1. **前台锁（focus stealing 保护）**：Windows 禁止后台进程随意抢焦点，直接调 `SetForegroundWindow` 大概率只是任务栏闪橙灯不激活。
   解法：`AttachThreadInput` 附加到当前前台线程后再置前（AutoHotkey 社区十几年验证过的稳定手法），Rust 里一次性写对即可。
2. **DPI 与多显示器**：混合 DPI 多屏下，若进程不声明 Per-Monitor DPI Aware v2，坐标会错位导致"打不中"。启动时一行 API 声明即可，但必须做。
3. **钩子超时**：低层鼠标钩子的回调会在**每一次鼠标移动**时被调用，系统默认只容忍约 300ms（`LowLevelHooksTimeout`），超时会被系统静默摘除钩子。
   因此架构上：钩子回调只做"识别到 Alt+右键 → 发消息给工作线程"（微秒级），窗口枚举、激活全部丢给独立工作线程。**这是本项目最重要的架构决策。**

小坑清单（都能低成本处理）：UWP 挂起态的 cloaked 窗口要用 `DWMWA_CLOAKED` 排除；子窗口句柄要 `GetAncestor(GA_ROOT)` 归一到顶层；最小化窗口矩形在 (-32000,-32000) 要排除；带阴影的窗用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 取真实可见边界更准；管理员权限运行的窗口（管理员终端、任务管理器）普通权限进程操作不了（UIPI）。

### 5.4 系统里最接近的现成方案（建议先体验对比，确认本工具的必要性）

| 方案 | 开启方式 | 与本需求的差距 |
|---|---|---|
| PowerToys Always On Top | Win+Ctrl+T | 聊天窗常驻置顶、永远可点，但会挡代码；相当于固定一对组合 |
| 悬停激活（X-Mouse） | 注册表 / 辅助功能设置 | 悬停即激活，但只激活**最顶层**窗口，激活不了被盖的；且"飘到哪激活哪"过于敏感 |
| Win+数字 / Alt+Tab | 系统内置 | 按键式、与位置无关，回到"视觉搜索"老路 |

三者都不满足"按位置激活**被盖住的**窗口"，所以这个工具值得做。

## 6. 交互设计（待你拍板）

- 触发：左Alt + 右键，**先按 Alt 或先按右键两种顺序都识别**（回调里用 `GetAsyncKeyState` 查即时状态，天然兼容）；
- 连按行为：第 1 次激活第二层，再按激活下一层……在被盖窗口间逐层下降，同位置两窗时即天然乒乓；
- 事件吞掉：触发的这一次右键被吞（目标程序不会弹右键菜单），**普通右键完全不受影响**；
- ⚠️ 冲突提醒：Alt+右键在少数软件有原生用途（Blender/Maya 的视图操作、mstsc 远程桌面、部分浏览器缩放手势）→ 需要**进程黑名单**机制（命中的进程让事件原样放行）；
- 可选增强（V1.1）：按住 Alt+右键不放 + 滚轮，可视化逐层轮换目标。

## 7. 功能范围

**MVP（V1.0）**
- 低层鼠标钩子（独立线程 + 消息循环）+ 事件通道 + 工作线程；
- "激活第二层被盖窗口"核心逻辑 + 前台锁绕过 + 吞事件；
- 进程黑名单（默认含 mstsc.exe）；
- 配置文件（config.toml，首次运行自动生成带注释默认配置）：**所有通用/默认设置统一于此单一文件**——触发键位、进程黑名单、权限策略（require_admin）、日志级别与大小上限等；任何字段缺失/非法自动回落默认值、不阻断启动（2026-10-22 确认，详见技术设计 §5）；
- 单实例互斥、开机自启动（HKCU Run 键，无需管理员）；
- 权限自检与提示：非管理员启动时托盘气泡提示限制 + 一键自提升（详见技术设计 §4.8）。

**候选迭代（V1.1+）**：滚轮逐层轮换、命中目标描边闪一下（视觉反馈）、配置热重载、计划任务静默提权自启动、窗口布局快照恢复。

## 8. 非功能需求

- 内存 < 15MB，空闲 CPU ≈ 0；单 exe 约 1~2MB，绿色免安装；
- 启动即生效，无需"先学习桌面"；支持 Win10 1903+ / Win11；
- 配置与日志位于 `%APPDATA%\fast-tab-click\`；**日志默认开启（info 级）**，单文件上限 10MB、超限自动清空重写（不滚动归档）——出问题始终有现场可查，磁盘占用恒定（2026-10-22 用户指定）。

## 9. Rust 技术栈草案

- `windows` crate（微软官方 Win32 绑定）；
- 线程模型：钩子线程（WH_MOUSE_LL + GetMessage 循环）→ mpsc/crossbeam 通道 → 工作线程（枚举 + 激活）；
- `serde` + `toml` 配置、`tracing` 日志（默认关闭）；
- 托盘（若要）：`tray-item`；单实例：命名 Mutex；MSVC 静态编译单文件发布。

## 10. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 杀软误报（全局钩子 + 吞右键属于敏感行为） | 分发/部署受阻 | 行为透明公开 + 文档指引白名单；正式版可考虑代码签名 |
| Alt+右键与个别软件冲突 | 可用性 | 黑名单机制 |
| 钩子被系统静默摘除后工具"失联" | 无感知失效 | 钩子线程极简 + 看门狗定期重挂 |
| 高完整性进程交互受限（UIPI：钩子收不到其输入事件、无法激活它） | 管理员窗口场景失效 | 启动自检 + 托盘一键自提升 / `require_admin` 强制（技术设计 §4.8） |

## 11. 决策记录（2026-10-22 已核对确认）

| 问题 | 决策 |
|---|---|
| 触发交互 | **左Alt + 右键，激活鼠标下方第二层被盖窗口**（默认值）；**触发键用户可自定义**（TOML `[trigger]` 节：修饰键任意组合 × 右/中/侧键，重启生效，非法配置回落默认）；滚轮逐层轮换不进 MVP，列为 V1.1 候选；保留进程黑名单（默认含 mstsc.exe，与改键互补：改键解决全局习惯冲突，黑名单解决个别软件放行） |
| 界面形式 | **保留托盘图标**（无主窗口）：托盘菜单提供 暂停/恢复、开机自启动、退出 |
| 权限策略 | 核心功能**不需要管理员**，V1 默认**普通权限**运行（2026-10-22 补充确认）；启动自检权限（TokenElevation），非管理员时**托盘气泡提示**（措辞如实：日常场景可用、管理员窗口场景受限）+ 托盘菜单【以管理员身份重启】一键自提升（UAC 拒绝则维持普通运行）；`require_admin=true` 可强制管理员启动（UAC 拒绝则退出）。以管理员运行可消除 UIPI 两限制（管理员窗口前台时触发失效、无法切换管理员窗口） |
